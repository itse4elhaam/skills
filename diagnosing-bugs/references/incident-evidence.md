# Incident evidence

Start with the exact reported behavior, device or entry point, time window and running revision. When the user says it happened again, inspect earlier attempts and current settings before repeating them. Separate retained evidence from logs that were never captured or have expired.

Before announcing a monitor is ready, record a representative event and verify the monitor survives it. Check timestamps and that the intended device or process generated the event. A wireless-mouse recording cannot establish what the touchpad did.

Keep observed sequence, candidate mechanism and attributed cause distinct. State the next observation that would distinguish the remaining explanations. Missing reproduction permits bounded investigation; it does not justify promoting a plausible theory to a proven cause.

Restore usability when authorized even if the cause is unknown. Record temporary changes and restore settings when an experiment ends. Call a reset recovery, a protective workaround mitigation, and a repair verified only when the evidence reaches the original symptom. Test a recovery detector against both a representative failure and healthy behavior, with bounded resets and an explicit blind spot.

Match verification to the user's action and installed app. A synthetic test may cover state transitions without proving physical input, focus, microphone capture or a real shortcut. Name that gap. Do not interrupt the user's desktop or use live devices beyond the agreed testing boundary.

Leave durable diagnostics for the next occurrence using logging-and-monitoring. End with what was observed, what was recovered or changed, what remains unconfirmed, and how the next incident can be investigated.
